**Author:** Bhupesh Chandra Dimri

## One-liner

A reproducible analytics pipeline that forecasts service KPIs, catches
bad data before it reaches a dashboard, and tells you which operational
lever actually moves SLA attainment — built in **R**, and replicated in
**STATA, SPSS and SAS** on the same data, so the results can be checked
in whatever tool the team uses.

## Why R / STATA / SPSS / SAS — and not deep learning

The job description asks for Excel (VBA), SQL, Power BI, and *exposure*
to Python, R, SPSS, SAS or STATA. It asks for dashboards, KPI tracking,
data-quality monitoring and documentation — not deep learning. So this
project is deliberately an **analytics + forecasting project**
(statistical modeling, time-series forecasting, anomaly detection), not
a transformer demo. The differentiator is **cross-tool validation**:
the same data, the same train/test split, the same metrics, computed
independently in four tools. If the numbers agree across tools, the
analysis is right; if they disagree, the code is wrong somewhere.
That is the check a hiring manager can actually verify.

## The three problems

| # | Problem (from the JD) | Type | Approach |
|---|---|---|---|
| 1 | Forecast KPIs / service performance (14-day ahead) | Time series / regression | Seasonal naive, Holt-Winters, linear regression, random forest, gradient boosting |
| 2 | Monitor data quality, troubleshoot integrity issues | Anomaly detection | Z-score rule (\|z\| > 4) on pipeline-health features |
| 3 | Link operational KPIs to outcomes; benchmark service lines | Driver analysis | Gradient boosting + permutation importance; per-channel benchmark |

## Data — synthetic, labelled as such

`data/synthetic/` is generated by `R/01_data_generation.R`
(`set.seed(42)`): five service channels (Helpdesk, Onboarding, Billing
Support, Field Service, Publishing Ops), 730 days of daily KPIs
(2024-01-01 to 2025-12-30), plus a daily pipeline-health log with 25
injected data-quality incidents (late feed, missing batch, duplicate
load, null spike). **No real client or personal data is used.**

| File | Rows | Grain |
|---|---|---|
| `kpi_daily.csv` | 3,650 | channel × day |
| `pipeline_health_daily.csv` | 730 | day |

## Cross-tool replication

| Tool | Scripts | Status |
|---|---|---|
| R (reference) | `R/*.R`, `run_all.R` | Executed here; tests pass |
| STATA | `stata/*.do` | Authored + syntax-reviewed; run `do stata/01_data_prep.do` … `04_drivers.do` in Stata 17+ |
| SPSS | `spss/*.sps` | Authored + syntax-reviewed; run in SPSS Statistics 28+ |
| SAS | `sas/*.sas` | Authored + syntax-reviewed; run in SAS 9.4 M6+ / Viya |

STATA / SPSS / SAS were **not executed on this machine** (commercial
software not installed). They replicate the same data, the same
train/test split (last 61 days = 2025-11-01 to 2025-12-30) and the
same metrics (MAE / RMSE / MAPE; precision / recall / F1), so running
them in the licensed application reproduces the comparison table.
Where a tool lacks a model (SPSS has no built-in random forest),
that is stated in the script — nothing is faked.

## Results (measured on the 61-day hold-out)

See `reports/model_report.md` for the full numbers. In brief:

- **Forecasting:** random forest is the best SLA forecaster
  (MAPE 0.80% on the 61-day hold-out); linear regression is the
  best volume forecaster (MAPE 3.05%). Holt-Winters gives an
  honest 14-day-ahead SLA forecast (MAPE 0.83%).
- **Anomaly detection:** the z-score rule (|z| > 4) catches all
  25 injected incidents — precision 0.714, recall 1.000,
  F1 0.833 (35 days flagged, 10 false alarms).
- **Drivers:** backlog pressure dominates SLA attainment
  (permutation importance 0.76); staffing coverage is second
  (0.09), system uptime third (0.07). Onboarding runs lowest
  (mean SLA 93.1%) vs Helpdesk highest (96.9%).

## Honest limits

- Synthetic data: magnitudes and rankings are illustrative, not
  evidence about any real client.
- Same-day operational features are used only for driver analysis,
  never for forecasting (that would leak).
- A 14-day forecast degrades with horizon; the reported 14-day
  MAPE is the honest number, not the 1-step MAPE.
